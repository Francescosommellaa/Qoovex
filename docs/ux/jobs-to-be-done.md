# Jobs To Be Done

## Scopo

Tradurre Qoovex in progressi concreti che uno chef cerca di ottenere, evitando
di progettare o comunicare il prodotto come un catalogo di feature.

## Job principale

**Decisione proposta**

> Quando ricette e informazioni operative sono sparse tra strumenti diversi,
> voglio creare una base professionale unica da cui ottenere gli output che mi
> servono, così posso lavorare e consegnare più velocemente senza riallineare
> tutto a mano.

## Decisioni

**Decisione proposta**

- Il job principale è creare una base riusabile, non archiviare ricette.
- Menu e lista sono i primi output da rendere comprensibili.
- Il Piano di lavoro dimostra continuità operativa, non project management.
- Explore viene dopo l’attivazione core.

## Job 1: Mettere ordine nell’archivio professionale

| Dimensione | Definizione |
| --- | --- |
| Situazione | Le ricette sono distribuite tra file, note, fogli e memoria. |
| Motivazione | Ritrovare, aggiornare e riusare il lavoro. |
| Risultato desiderato | Una ricetta strutturata, completa e recuperabile. |
| Strumenti attuali | Quaderni, Word/Docs, Excel/Sheets, PDF, Drive. |
| Frustrazione | Duplicati, versioni incoerenti, formati diversi. |
| Promessa Qoovex | Un archivio professionale che alimenta altri output. |
| Feature | Ricette, ingredienti, allergeni, nutrizione, ricerca. |
| Prova landing | Prima/dopo di una ricetta dispersa e poi strutturata. |
| Impatto prodotto | Il primo valore deve arrivare prima di configurare altre aree. |

**Punto da validare**

Importazione e inserimento iniziale devono essere testati come principale
barriera all’attivazione.

## Job 2: Trasformare ricette in menu aggiornabili

| Dimensione | Definizione |
| --- | --- |
| Situazione | Serve creare o aggiornare un menu per un cliente o locale. |
| Motivazione | Consegnare velocemente un output coerente. |
| Risultato desiderato | Comporre il menu senza ricopiare dati già inseriti. |
| Strumenti attuali | Canva, Word, PDF, menu builder, gestionale. |
| Frustrazione | Modifiche ripetute e allergeni disallineati. |
| Promessa Qoovex | Il menu nasce dalle ricette e ne riusa i dati. |
| Feature | Menu, sezioni, allergeni, QR. |
| Prova landing | Aggiornamento della ricetta che si riflette nel flusso menu. |
| Impatto prodotto | La relazione ricetta-menu deve essere evidente e controllabile. |

## Job 3: Gestire allergeni e nutrizione con meno lavoro manuale

| Dimensione | Definizione |
| --- | --- |
| Situazione | Serve completare schede o menu con informazioni alimentari. |
| Motivazione | Ridurre ricerca e trascrizione manuale. |
| Risultato desiderato | Dati utili, tracciabili e verificabili prima della pubblicazione. |
| Strumenti attuali | Tabelle manuali, database esterni, consulenze, copia-incolla. |
| Frustrazione | Dati incompleti, fonti non chiare, rischio di errore. |
| Promessa Qoovex | Calcolo e aggregazione assistiti con controllo professionale. |
| Feature | Ingredienti, stato di verifica, allergeni, intervalli nutrizionali. |
| Prova landing | Fonte, stato di verifica e possibilità di revisione. |
| Impatto prodotto | Mai nascondere incertezza o presentare stime come certificazione. |

**Fatto confermato**

Qoovex non deve dichiarare infallibilità o sostituzione della verifica
professionale.

## Job 4: Preparare una lista a partire dal lavoro già fatto

| Dimensione | Definizione |
| --- | --- |
| Situazione | Ricetta o menu sono definiti e serve preparare gli ingredienti. |
| Motivazione | Evitare una nuova trascrizione. |
| Risultato desiderato | Lista aggregata, leggibile e spuntabile. |
| Strumenti attuali | Carta, note, fogli, messaggi. |
| Frustrazione | Ingredienti dimenticati, somme manuali e unità incoerenti. |
| Promessa Qoovex | Generare la lista da ricetta o menu. |
| Feature | Lista della spesa e aggregazione ingredienti. |
| Prova landing | Menu selezionato → lista generata → elementi spuntati. |
| Impatto prodotto | Il percorso dalla fonte deve essere più rapido della lista manuale. |

**Fatto confermato**

La Lista della spesa non gestisce prezzi nello scope corrente.

## Job 5: Portare una ricetta nel lavoro della brigata

| Dimensione | Definizione |
| --- | --- |
| Situazione | Il creator deve far eseguire attività a una o più persone. |
| Motivazione | Dare istruzioni chiare e sapere cosa è stato completato. |
| Risultato desiderato | Task collegati al contesto corretto senza inviare file separati. |
| Strumenti attuali | WhatsApp, carta, lavagne, task manager. |
| Frustrazione | Informazioni fuori contesto e aggiornamenti dispersi. |
| Promessa Qoovex | Piano di lavoro collegato a snapshot della ricetta. |
| Feature | Piani, membri, task, snapshot, completamento, notifiche. |
| Prova landing | Creator assegna → membro consulta → completa → creator riceve notifica. |
| Impatto prodotto | Il membro deve vedere solo ciò che serve per agire. |

## Job 6: Riutilizzare lavoro professionale pubblico

| Dimensione | Definizione |
| --- | --- |
| Situazione | Serve ispirazione o una base da adattare. |
| Motivazione | Ridurre il lavoro da zero mantenendo attribuzione. |
| Risultato desiderato | Trovare e duplicare una ricetta utile nel proprio workspace. |
| Strumenti attuali | Social, siti, PDF, screenshot e copia manuale. |
| Frustrazione | Contenuti non strutturati e difficili da trasformare in lavoro. |
| Promessa Qoovex | Esplorare contenuti professionali e riusarli come base. |
| Feature | Explore, pubblicazione e fork. |
| Prova landing | Non necessaria nella prima versione della hero. |
| Impatto prodotto | Explore non deve interrompere il percorso di attivazione core. |

## Priorità

**Decisione proposta**

1. Archivio ricette.
2. Ricetta → menu e allergeni.
3. Ricetta/menu → lista.
4. Ricetta → Piano di lavoro.
5. Explore.

L’ordine indica la sequenza di comprensione e attivazione, non lo stato
implementativo.

## Regole

- Ogni feature deve servire almeno un job prioritario.
- Descrivere situazione e risultato prima della soluzione.
- Misurare il tempo al risultato, non solo il completamento di schermate.
- Un job non è “usare la feature”.
- Non inserire roadmap AI nei job v1.

## Esempi

Corretto:

> Quando devo aggiornare il menu di un cliente, voglio riusare i dati delle
> ricette, così non devo ricontrollare ogni allergene in più file.

Errato:

> Voglio usare il menu builder per creare un menu.

## Anti-pattern

- Job formulati come desiderio di una feature.
- Risultati vaghi come “essere più efficiente”.
- Ignorare strumenti e comportamenti attuali.
- Trattare Explore come job principale.
- Promettere automazioni non presenti.

## Punti da validare

- Job che innesca la prima registrazione.
- Job che giustifica il pagamento.
- Frequenza e intensità di ciascun job per segmento.
- Quale output costituisce il primo momento di valore.
- Quanto contano importazione e riuso rispetto alla creazione manuale.

## Checklist finale

- [ ] Ogni job contiene situazione, motivazione e risultato.
- [ ] Sono indicati strumenti attuali e frustrazioni.
- [ ] Ogni promessa ha una prova landing.
- [ ] L’impatto sul prodotto è esplicito.
- [ ] L’ordine dei job guida onboarding e comunicazione.
- [ ] Nessun job richiede capacità fuori scope.
